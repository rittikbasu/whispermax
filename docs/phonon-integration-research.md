# Phonon integration recommendation

Research date: 2026-10-09. Scope: the [Detta Neural Engine article](https://www.fermionresearch.com/research/detta-neural-engine/), official runtime sources, and this checkout. This report records the research and the implementation decisions made on `feat/phonon-asr`.

## Decision

Use native Phonon Core ML on the Neural Engine as WhisperMax's sole recognizer, with no runtime Whisper fallback. This follows the user's explicit product choice. The development corpus shows equal aggregate edit counts but meaningful condition-specific losses, so the implementation should make no blanket accuracy-superiority claim. Preserve Whisper only in the local offline comparison harness. The 10-second Core ML recipe is the best of the tested local settings.

## Implementation status — 2026-10-09

- The app now chooses Phonon directly; backend environment selection and runtime Whisper/Qwen paths have been removed.
- Phonon uses the pinned 1.1.2 Core ML package, its single 10-second encoder function, a 9.98-second raw single-shot ceiling, and deterministic non-silent warm-up. The 9.98-second setting accounts for the package's 20 ms log-mel duration adjustment.
- VAD now has an actor-isolated owner, prepares before the app reports ready, rejects clips without a credible speech region, then passes the original audio to Phonon for its own windowing.
- Model delivery pins the Hugging Face repository revision `1143812fd4236522232a8c33e3115f0577e3cd7d`, downloads eight files (345,023,465 bytes total), verifies their SHA-256 hashes, stages the bundle, preserves interrupted-download resume data, and recovers the previous model if the app exits during replacement. The eight hashes and sizes match the local official package already used for evaluation.
- The app target excludes `WhisperEngine.swift` and `TranscriptionChunkPolicy.swift`; Whisper remains compiled only by the private VAD comparison harness. The vendored Whisper framework remains in the app for Silero VAD. Qwen's app prototype and worker were removed.
- The exact Debug app build, VAD comparison-harness build, and `git diff --check` pass. A fresh install was exercised on this Mac by temporarily moving the verified installed model aside, launching the signed feature build, downloading the pinned 345,023,465-byte bundle, preparing Phonon and VAD, and completing onboarding. All eight downloaded assets matched their pinned byte counts and SHA-256 hashes. The completion action appeared only after preparation finished. Then an intentionally malformed same-size manifest reproduced the preparation error. Retry hashed the package off the main thread, detected the corrupt asset, launched the existing model-repair download flow, verified and installed all eight assets, prepared Phonon/VAD, and returned onboarding to Ready without external file repair. The original installed package and onboarding marker were restored afterward; all eight original assets were reverified, and the generated fresh duplicates were removed.
- The installed-model onboarding path had also been exercised earlier, including readiness gating on Phonon and VAD. Startup recovery was exercised by placing the prior model at the downloader's `.previous` path and relaunching; the canonical model was restored. That reproduces the on-disk state after a crash between replacement renames, though it is not a process kill during the rename window.
- The Word Dictionary currently applies post-decode spelling/casing substitutions; the pinned Phonon Core ML API receives no prompt or hotwords. Its 25-hotword limit therefore does not justify capping saved dictionary entries. If a future adapter exposes hotwords, cap only the terms passed for each decode and retain the full user dictionary.
- A controlled local TTS phrase reached TextEdit through the global hotkey and Direct Insert. A duplicate insertion incident coincided with both the feature build and the installed `/Applications/whispermax.app` running; the installed copy was stopped. The feature app is currently stopped after restoring the original model package, so a single-process repeat remains necessary to confirm the duplicate is gone. Silence rejection was also confirmed once with no text inserted. Cancel during inference, clipboard fallback, microphone switching, sleep/wake, offline installed-model launch, download retry after a network failure, and human-speech first/final syllable capture remain open.

### 1.1.2 recipe ablation

All three recipes used the same 67 recordings and 1,166 normalized reference words for three repeats. The current 10-second path scored 96 edits (8.23%); lowering `bandMinSeconds` to eight seconds scored 109 (9.35%); loading the official `[5, 10, 15, 35]` function ladder with 15-second windows scored 100 (8.58%). Keep the current 10-second recipe. It measured 64 ms warm p50 and 159 ms p95 in the repeated run. The default ladder added about 191 seconds of first-use compilation across functions, with the 35-second function alone taking about 97 seconds to compile. Its worker physical peak was about 191 MB, while the separately sampled ANE compiler service grew to about 1.29 GB. Those memory scopes are separate and not an app total. Results live only in Yaplab's ignored private runs/reports.

## What the article establishes

Fermion reports an M5 MacBook Air with 16 GB: median key-up-to-text improves from 330 to 260 ms; idle memory falls from 1.8 GB to under 0.3 GB without Gluon, or 0.6 GB with it loaded; typical dictation peaks at 0.81 GB and heavy ten-minute dictation at 1.1 GB. First use becomes available in about a minute and reaches full speed in about four. Recognition uses the Neural Engine; Gluon separately edits transcripts on the GPU, adding roughly 80 ms for a typical sentence. Dictionary bias acts during recognition. These are vendor app measurements. The article does not disclose sample count, duration mix, tail latency, memory counter/process scope, or insertion destinations. Its results justify measuring the same phases locally, not adopting its figures as M1 Pro guarantees. [Source](https://www.fermionresearch.com/research/detta-neural-engine/).

The separate [Phonon-2 report](https://www.fermionresearch.com/research/phonon-2/) reports seven-set average WER of 5.21%, versus Whisper Turbo's 6.58%, with losses on LibriSpeech-other and SPGISpeech. Its 174× Apple result is MLX on M5 with load excluded; the 104.9× Core ML comparison row is Parakeet. The newer [official Core ML card](https://huggingface.co/FermionResearch/Phonon-2-CoreML) publishes Phonon's own ANE measurements and package. Historical statements in our evaluation note that no separate official Core ML artifact exists are now outdated.

## Local fit and measurement boundaries

The 67-recording development corpus has 61 speech clips and six controls. Production Whisper and the integrated 10-second Phonon path each make 96 edits over 1,166 normalized words. Phonon improves short speech, 35 versus 49 edits, but worsens medium speech, 58 versus 39, losing on ten of twelve medium takes. The small full-fan source contains matched Mac/AirPods recordings; its six speech clips produce 11 Phonon edits versus three Whisper edits. It is not six independent AirPods-microphone samples. All six controls are rejected by the app VAD gate. [Evaluation note](phonon-asr-evaluation.md); [benchmark protocol](/Users/rittikbasu/dev/AI/yaplab/BENCHMARK.md).

The app-engine runner measures about 64–75 ms warm inference median and 99/256 ms median/p95 with audio decode and VAD. Its roughly 79 MB physical footprint excludes the GUI and separately observed ANE compiler service. In the GUI run, the app process was around 80 MB while the separate ANE compiler service peaked around 1.17 GB RSS; these are different memory counters and not a combined app footprint. The GUI first insertion was about 10.8 seconds, with roughly ten seconds in cold VAD, followed by a 727 ms warm insertion in the earlier playback check. A later warm smoke check captured a 5.5-second local TTS phrase through the Mac microphone and inserted the complete expected sentence into TextEdit. This validates one controlled hotkey-to-insert path; it does not establish human-speech quality, AirPods behavior, or noisy-room performance. [Evaluation note](phonon-asr-evaluation.md). These GUI observations should be read with their separate scopes.

Our older MLX runs, including Detta's packed adapter at about 1.65 GB, measure a different runtime. The newer private Detta 1.0.26 audit found the same model checksum, ANE recognition, dynamic encoder selection, capture pre-roll, partial decoding, hotword bias, and separate SmolLM2-based Gluon cleanup. On nine full-fan Mac recordings, blanket 250 ms padding increased errors from 11 to 15; no-padding matched the public CLI. Its 263.5 MiB adapter footprint excludes the full app and cleanup model. These observations explain why neither the earlier MLX results nor our small worker footprint reproduces the article's whole-app memory claim. [Local signed-bundle audit](/Users/rittikbasu/dev/swift/whispermax/.private-bench/detta-inspect/architecture-1.0.26.md).

## Initial findings and resolutions

1. **Readiness excluded VAD. Fixed.** VAD now runs in its own actor and loads during model preparation. The app does not report ready until both VAD and Phonon have prepared. A passing VAD gate keeps the original audio. [AppController](../WhisperMax/Core/AppController.swift); [SpeechActivityService](../WhisperMax/Audio/SpeechActivityService.swift).
2. **The warm-up was skipped. Fixed.** The previous all-zero warm-up exited at the package silence check. The engine now uses deterministic non-silent input and discards its output. [Engine](../WhisperMax/Transcription/PhononCoreMLEngine.swift); [pinned Segmenter source](https://raw.githubusercontent.com/fermionresearch/phonon-coreml/1.1.2/Sources/PhononCoreML/Segmenter.swift).
3. **The quiet-cut interval was empty. Tested and left unchanged.** The current 10-second window and 10-second lower bound do not leave a useful search interval. Lowering the band minimum to eight seconds worsened this corpus from 96 to 109 edits, so the production recipe retains the tested current windowing with two-second overlap and rescue. [Engine](../WhisperMax/Transcription/PhononCoreMLEngine.swift); [pinned Windower](https://raw.githubusercontent.com/fermionresearch/phonon-coreml/1.1.2/Sources/PhononCoreML/Windower.swift).
4. **The nominal function boundary exceeded capacity. Fixed.** The pinned encoder selects a function using mel-frame duration plus 20 ms, whereas the single-shot decision uses raw sample duration. Set the app's raw single-shot ceiling to 9.98 seconds for the 10-second function. Phonon continues to window longer input; the app does not truncate it. [Pinned Transcriber](https://raw.githubusercontent.com/fermionresearch/phonon-coreml/1.1.2/Sources/PhononCoreML/Transcriber.swift).
5. **Dictionary bias is unavailable in Swift 1.1.2. Documented.** The Phonon adapter cannot pass a recognition prompt or hotwords. The app's dictionary only applies capitalization when the recognized words already match; the UI now says so. Do not claim it improves recognition until a compatible upstream API or a separately reviewed port is available. [Engine](../WhisperMax/Transcription/PhononCoreMLEngine.swift); [formatter](../WhisperMax/Core/TranscriptFormatter.swift); [generic hotword documentation](https://raw.githubusercontent.com/fermionresearch/phonon/main/docs/hotwords.md).

3. Measure whole-app stop-to-insert latency across repeat runs and capture a controlled active-dictation memory sample, reporting the app process and ANECompilerService separately. The settled post-setup idle sample measured about 85 MB app physical footprint, 127 MB app high-water, 127 MiB RSS, 64 KB current Neural Engine allocation with a 336 MB high-water, and 1.1 MB ANECompilerService RSS. That process had not dictated, so its high-water is not an active-transcription peak. An earlier post-dictation sample measured about 90 MB app footprint and a 138 MB app high-water. These counters have different scopes and times and must not be added or compared directly with Detta's published whole-app numbers.
4. Keep the 67-recording corpus and the offline Whisper comparator in Yaplab's ignored private storage. The current results show a tie overall and local losses for medium clips and AirPods/full-fan; the app decision is a speed/runtime choice, not evidence of universal accuracy superiority. A new unseen holdout is only needed before making a stronger accuracy claim or changing the recipe again.
5. Sol 6.1 found two connected P2 gaps: preparation Retry could loop on a same-size corrupt package, and a failed repair download lost the forced-repair state on the next retry. Retry now verifies pinned hashes off the main thread, and the repair requirement persists through download failures until a verified package installs. The same-size corruption detector smoke test and successful app repair flow pass; retry after a real network failure remains unverified. The final spec pass found no other P1/P2 issue. No XCTest target exists. The VAD framework is still required; only the Whisper recognizer and its model setup have been removed from the product target.

Keep the pinned English normalizer. Compare model text separately from formatter output and inserted text, and keep mic/fan claims limited to recordings with verified condition labels. Do not tune with the existing holdout and then call it independent confirmation.
